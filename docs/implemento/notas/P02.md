# P02 — App P0: versão no pedido e leitura tolerante (app, ∥ P03)

Nota de desenho (P00, 23/09). Repositório `mobile-flutter`, branch **`feat/implemento`** (criada no P00 de `origin/main` `9335286`, versão `1.4.1+24`; **sem upstream**, para nenhum push cair na `main`). Plano: §6.7 "P02", §5.4, §2A.12, D-17, D-25, V16.

## Escopo exato

Um patch OTA **só de Dart**, que o app instalado possa receber pelo Shorebird **antes** de qualquer mudança na API:

1. **Cabeçalho de versão** em todo request (`lib/core/network/dio_client.dart:160-170`): `X-App-Version` (de `package_info_plus`, ex.: `1.4.1+24`) e `X-App-Patch` (número do patch do `shorebird_code_push`, ou vazio). É o que o censo (G3, P06) vai contar — o P00 confirmou que **hoje não há como saber a versão do parque**: o User-Agent é `Dart/3.12 (dart:io)` para todos e as colunas `appVersion` de `PpeDeliverySignature`/`WarningSignature` estão vazias.
2. **426 → tela "Atualize o app"** (`lib/core/network/api_exception.dart:68-75,121-160` + interceptor novo): bloqueante, com botão que força `checkForUpdate` do Shorebird e o link `/install`. O "Agora não"/soneca (`lib/features/updates/ota_update_service.dart:55-130`, `native_update_service.dart:1-30,118-135,224-248`) deixa de valer depois de um 426. **Nenhum servidor responde 426 na Fase A** (só na R-C): o comportamento visível não muda.
3. **Leitura tolerante** do formato novo, sem deixar de ler o velho:
   - `lib/data/models/task.dart` (parse de `truck`, `:135-262`, `:222-245`, `:468-486`): `j['implement'] ?? j['truck']`, `type ?? implementType`; aceita `frontSideMeasure` e `rearDoor*` se vierem (e os ignora na tela, que não os mostra ainda).
   - **Série** (DD1): `_serialOf(j) = j['implement']?['serialNumber'] ?? j['serialNumber']` em `Task` (`task.dart:438`), `BudgetTaskLite` (`lib/features/financial/budget.dart:220`) e `BillingTask` (`lib/features/financial/billing_task.dart:112`). Sempre string ou null.
   - `lib/features/financial/budget.dart:137-243`; `billing_task.dart:17,29,38,42,119-120`: o mesmo recuo `implement ?? truck`.
4. **Parar de pedir `customerConfigs.include.responsible`** (`budget.dart:531,1187`): a relação morreu em 18/09 e o zod descarta calado.
5. **Defaults "Refrigerado" vazios** (D-25): `lib/features/financial/budget/budget_form_screen.dart:206-207` e `lib/features/production/task_form_screen.dart:181` (o tipo nasce vazio, como no web).

**Regras do app** (§6.7): nunca `dart format` global (formatar só os arquivos tocados); **nenhum glifo de ícone novo** (a fonte Tabler é tree-shaken; glifo novo faz o Shorebird recusar o patch); não unificar `kImplementTypeLabels` com `kNfseImplementTypeLabels`. **Publicar o patch Shorebird é do dono**, não do agente: o pacote termina com o patch pronto e o comando anotado.

### Desvios

1. **O patch não pode sair de `feat/implemento` (nem da main)** — o plano supunha que sim. Depois da tag `v1.4.1+24` a main tirou 5 dependências (`printing`, com código nativo, `jwt_decoder`, `flutter_colorpicker`, `fl_chart`, `collection`), apagou `assets/branding/sergio-signature.png` e passou a usar 3 glifos Tabler que a release não tem (`arrows_join`, `file_download`, `receipt_2`). O Shorebird recusa esse patch (asset/nativo), e ele levaria ao parque tudo o que a main ganhou desde 18/09 (orçamento de N veículos, faturamento, paridade). Por isso o P02 foi **portado** para `patch/p02-sobre-1.4.1+24` (lá o modelo do orçamento ainda é `QuoteTaskLite` em `task_quote.dart`; mesmas funções, mesmo teste de contrato adaptado aos nomes). **Comando (do dono):** `git switch patch/p02-sobre-1.4.1+24 && scripts/shorebird.sh patch-all`. ⚠️ Se já houver patch publicado para `1.4.1+24` construído de outra base, este o substitui — conferir `shorebird patches list --release-version=1.4.1+24` antes.
2. **`X-App-Platform`** é um terceiro cabeçalho (o pedido do pacote falava em "e plataforma"); `X-App-Version`/`X-App-Patch` ficaram com os nomes exatos. O P06 pode ignorá-lo ou contá-lo.
3. `lib/app.dart` (fora da lista de arquivos da nota) ganhou uma linha: montar `UpgradeRequiredHost` no `builder`. `lib/features/files/layout/layout_dimensions.dart` (listado no §6.12 para P11/P24) foi tocado **só** no parse do lado, por pedido explícito do pacote; a `frente` de verdade no enum continua do P24.
4. O parse de `BudgetPayer.responsible` não foi apagado (só o pedido): a seção de configuração do orçamento ainda o lê, e apagá-lo é tela (P24).
5. Nada foi testado em aparelho: 426 real só existe na R-C; a tela foi provada em widget test.
