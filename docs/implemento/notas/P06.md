**Runbook da R-A (do dono; o agente não publica)**
1. `pg_dump` de produção (o de sempre, antes de migrar).
2. No servidor: `git pull` da branch, `pnpm install`, **build antes de migrar** (`npm run build`) — M0 é aditiva, mas a ordem da casa é essa.
3. `npx prisma migrate deploy` (aplica só `20260930100000_arte_estados_e_tipos`; sem janela de 500: o código velho ignora valor e tipo novos). `npx prisma migrate status` limpo.
4. `systemctl restart` da unidade da API (**não** `pm2`); conferir `build-info` com o commit novo (health 200 pode ser o processo velho).
5. Conferir no log: `journalctl -u <unidade da api> --since '10 min ago' -o cat | grep '\[CENSO\]'` mostra linhas, e as do app trazem `"v":"1.4.1+24"` (depois do patch P02) ou `"v":null` (app sem o patch, web, AnkaaAero `"ua":"AnkaaAero/1"`).
6. Preflight do web: `curl -si -X OPTIONS https://<api>/tasks -H 'Origin: https://<web>' -H 'Access-Control-Request-Method: GET' -H 'Access-Control-Request-Headers: x-client'` tem `x-client` no `Access-Control-Allow-Headers`. **Só então** o build do web liga `VITE_SEND_X_CLIENT=1` (P03). Se houver nginx na frente respondendo CORS, a lista de lá precisa dos mesmos 4 cabeçalhos (não verificado: sem ssh).
7. A R-A também leva o patch P02 do app (dono). Depois: censo gravando ≥ 2 semanas (§10.2) → `census-to-fixture.ts` → `censo.json` → G4.

**Desvios**
1. `prisma migrate diff --from-url … --exit-code` sai **2**, não vazio: a deriva (446 linhas) é anterior e de construção — colunas geradas `*Normalized`, índices e tabelas de arquivo (`_DroppedTruckVinPlateText`) que vivem fora do Prisma (G25, `prisma/sql/objetos-pos-push.sql`). Prova de que M0 não deriva: o diff com o `schema.prisma` de antes acusa exatamente os 3 enums; o de depois não acusa nenhum.
2. O CORS (`src/common/config/security.config.ts`, `x-client`, `x-app-version`, `x-app-patch`, `x-app-platform`) não estava na lista de arquivos desta nota; veio do pedido da rodada e do P03 (§53 da nota dele). Os `@Options` à mão de `file.controller.ts` (serve/download/thumbnail) têm lista própria, mas o `enableCors` global responde o preflight antes deles; não mexi.
3. `X-App-Platform` também é registrado (a nota citava só versão, patch, `X-Client` e UA).
4. 404 (sem rota casada), OPTIONS e HEAD ficam **fora** do censo: sem rota não há padrão, e registrar a URL crua vazaria id; varredura de robô encheria o teto.
5. `test:census` roda em `ts-node --transpile-only` (não `tsx`): a parte F sobe um app Nest com decorators de parâmetro, que o esbuild do `tsx` recusa.
6. Quando o `censo.json` real for commitado, as formas que reproduzirem uma forma já conhecida como quebrada reprovam no G4 com o id `censo.…` (a lista `FORMAS_QUEBRADAS_CONHECIDAS` é por id): quem commitar acrescenta o id novo ali, ou conserta a forma.
