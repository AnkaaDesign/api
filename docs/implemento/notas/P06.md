## Escopo exato

1. **M0** `prisma/migrations/20260924100000_arte_estados_e_tipos/migration.sql`, com o SQL do §4.2 (os **cinco** valores de `LayoutApprovalSource`, inclusive `MIGRATED_ENVELOPE`; `ADD VALUE IF NOT EXISTS`; `CREATE TYPE` guardado por `pg_type`). Aplicar só no `ankaa_implemento` (`npx prisma migrate deploy`), depois `migrate status` limpo e `prisma migrate diff --from-url "$DATABASE_URL" --to-schema-datamodel prisma/schema.prisma --exit-code` vazio.
2. **`schema.prisma`: só os enums** — `LayoutStatus` + `PENDING_APPROVAL`, `SUPERSEDED`; `enum LayoutApprovalSource`; `enum RearDoorLeaves`. **Nenhum** modelo os usa ainda; **nenhum** espelho TS (`src/constants/enums.ts`) e **nenhum** rótulo: assim o contrato do G5 (`contracts/*.json` e as cópias do web e do app) não muda e o web e o app não precisam de commit. Os espelhos e rótulos entram com quem usa (P11b: `REAR_DOOR_LEAVES`; P12: `LAYOUT_STATUS` com 5 e `LAYOUT_APPROVAL_SOURCE`).
3. **G3 — censo de formas** (telemetria só de leitura): módulo novo `src/modules/common/census/` com um middleware Nest registrado em `app.module.ts` que, por rota (método + padrão do Express, não a URL crua), loga **só os caminhos de chave** de `include`/`select`/`where`/`orderBy` e do corpo (nunca valores; corpo multipart: só os nomes de campo), com `X-App-Version`, `X-App-Patch`, `X-Client` e o `User-Agent` reduzido (família: `Dart`, `AnkaaAero/…`, navegador). Formato: uma linha JSON por forma **nova** por processo (conjunto em memória com teto, como o F7 do G1: 2.000 formas, balde `(outros)`), prefixo `[CENSO]`. Não muda resposta nem status. `scripts/census-to-fixture.ts` lê o log (`journalctl`/arquivo) e gera as fixtures do G4 (`contracts/queries/censo.json`) — é o que os clientes **realmente** mandam, inclusive o app 1.4.1 e o `AnkaaAero`.
4. **G13 (lado API, só leitura)**: o mesmo middleware expõe `req.appVersion` (parse de `1.4.1+24`) para o G1 contar por versão. **Sem 426** (é o P31).
